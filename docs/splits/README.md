# CUB 데이터 분할

이 폴더는 팀 실험에서 사용할 이미지 ID 목록을 보관한다. 각 텍스트 파일의 한 줄은 CUB `images.txt`의 이미지 ID 하나이며, 사진이나 개인 경로는 포함하지 않는다. 노트북의 분할 코드로 생성한 목록 순서를 그대로 저장한다.

| 파일 | 개수 | 역할 |
| --- | ---: | --- |
| [train_ids.txt](train_ids.txt) | 4,794 | 가중치 학습 |
| [validation_ids.txt](validation_ids.txt) | 1,200 | 모델 선택과 Hard-class 선정 |
| [test_ids.txt](test_ids.txt) | 5,794 | 최종 평가 |
| [metadata.json](metadata.json) | 해당 없음 | 분할 설정, 생성 환경, 원본 메타데이터와 목록의 SHA-256 |

## 생성 기준

1. 공식 `train_test_split.txt`의 학습 이미지 5,994장만 검증 분할 대상으로 사용한다.
2. `images.txt` 순서대로 읽으며 같은 클래스의 이미지를 모은다.
3. 클래스도 최초 등장 순서로 순회한다. 하나의 `random.Random(42)` 객체로 각 클래스의 목록을 차례로 섞는다.
4. 클래스마다 `round(이미지 수 * 0.2)`장을 검증용으로 배정하고 나머지를 학습용으로 사용한다.
5. 공식 테스트 이미지는 원래 목록 순서로 유지한다.

현재 공식 학습 이미지가 클래스당 29~30장이므로 검증은 모든 클래스에서 6장씩이다. 원본 클래스 번호는 1~200이며, 모델용 레이블은 1을 뺀 0~199를 사용한다. 클래스 이름은 다운로드한 `classes.txt`에서 읽는다.

## 재현과 변경

[노트북](../../notebooks/dataLoader.ipynb)은 위 규칙으로 분할을 재생성한다. 이 파일들은 실험에 사용할 목록을 대조하기 위한 공유 기준이다. 노트북이 파일을 자동으로 덮어쓰지는 않는다.

같은 실험 비교에서는 이 목록을 공통으로 사용한다. 분할 설정을 바꾸면 세 ID 목록과 metadata.json을 함께 갱신하고, 실험 기록에 해당 커밋을 남긴다. 모델 초기화, 어그멘테이션, DataLoader의 학습 순서에 사용하는 난수는 이 분할 seed와 별도로 관리해야 한다.
